Access Key

What it is
The Access Key is a secret generated by the setup wizard when you first set up WhosWhoZoo. It's stored as a Cloudflare Worker secret and proves you are the owner of your worker. Think of it as a spare key for getting back in — not a second way to use the app. It can reset your passphrase, and that is all it can do: it cannot read your memory, sign you in, or export anything. Your passphrase is what protects your records.
When it's used
Initial setup only: you enter it once on the first connection screen alongside your Worker URL, then choose a passphrase. After that, your passphrase handles all logins.

Passphrase recovery: if you forget your passphrase, enter the Access Key on the login screen instead. It bypasses the passphrase check and lets you set a new one.
How to rotate it
The Access Key can only be rotated via the setup wizard at whoszoo.app/setup. It auto-detects your existing install; check the "Rotate my Access Key" box on the Access Key step before deploying. Settings has a one-line pointer to this ("Access Key can be rotated at whoszoo.app/setup") next to Change passphrase, but rotation itself is not something the app can do — by design, a Worker cannot write its own secrets. Your passphrase is unaffected by key rotation.
If you lose your Access Key: you can still use your passphrase to log in normally. The Access Key is only needed for passphrase recovery. If you lose both, a clean reinstall is the only path forward (see below).

Your Cloudflare API Token

It is more powerful than your Access Key
The token you created during setup can read and change anything in your Cloudflare account — including your memory files, directly, without your passphrase. Everything WhosWhoZoo does to protect your memory happens inside the app: your passphrase, auto-lock, the Access Key limits, the security log. A live Cloudflare token goes around all of it, and nothing it does will ever appear in /security.
You can delete it — and we recommend it
Setup is the only thing that token is for. Your app doesn't use it: the Worker reaches your memory through internal bindings wired up at install time, not through the Cloudflare API. Delete the token and everything keeps working exactly as it does now. Go to Cloudflare → My Profile → API Tokens and delete the one you made during setup.
You'll need a new one to update
That's expected and takes about a minute — create a fresh token with the same permissions, run the wizard at whoszoo.app/setup, then delete it again. Please don't skip updates to avoid this. Running an old version is a bigger risk than briefly holding a token. Deleting a token only removes a way of administering your Cloudflare account — it never touches what's stored in it, so your memory, passphrase and Access Key are all unaffected.
Prefer to keep it? That's a reasonable choice — just treat it like the password to your whole account. Store it in a password manager rather than a notes app, and turn on two-factor authentication for your Cloudflare login.

API Keys

ANTHROPIC_API_KEY Claude AI — all chat and memory analysis. Check usage at console.anthropic.com
OPENAI_API_KEY Marin & Onyx voices (TTS). Check usage at platform.openai.com/usage
ELEVENLABS_API_KEY Brittney & Callum voices. Check usage at elevenlabs.io/app/subscription
Updating a key from within the app
Go to Settings → API Keys. Paste your new key and tap Save. The field clears immediately — values are write-only and cannot be read back from the app. A Clear override link appears after saving; tapping it removes the app-saved key and reverts to the key set during installation.
The Cloudflare API key is setup-only. It is used by the web setup wizard to deploy your worker — it is never stored in the app and does not appear in Settings.

Clean Reinstall

This deletes all your memory data. Export a backup first using /export in the chat. The exported zip contains all your memory files as plain text.
1 In the app, type /export and download your backup.
2 Go to the Cloudflare dashboard → Workers & Pages → find whoszoo-worker → delete it.
3 In the Cloudflare dashboard → KV → find the MEMORY namespace → delete it. This removes all stored memory, auth config, and API key overrides.
4 Go to whoszoo.app/setup and run through it fresh. It will create a new worker, a new KV namespace, and generate a new Access Key.
5 After setup, use /import to restore your memory files from the backup zip.

What Setup Deploys

Cloudflare Worker The app backend — handles all chat, memory reads/writes, and auth. Your Anthropic key lives there and never reaches your browser.
KV Namespace (MEMORY) 12 plain markdown files storing your memory, plus auth config, cost log, and API key overrides saved in-app.
Worker Secrets ANTHROPIC_API_KEY, OPENAI_API_KEY, ELEVENLABS_API_KEY, WORKER_KEY (Access Key), USER_NAME. Write-only — not readable even via Cloudflare dashboard.
Frontend (static assets) The app UI is served directly from the Worker via an assets binding — no separate Cloudflare Pages deployment needed.

Memory File Format & Seeding

All memory is stored as plain markdown files. Every record is a ## Section header followed by free-form text. You can create or edit these files in any text editor and import them with /import. When editing records directly with /edit, a Markdown reference → link appears above the edit textarea.

The 12 memory files
people.mdActive — people you know
loops.mdActive — open items, follow-ups, commitments
reflections.mdActive — journal entries and personal notes
fragments.mdActive — loose facts, ideas, observations
archive_people.mdArchive tier — people you've filed away
archive_loops.mdArchive tier — closed loops
archive_reflections.mdArchive tier
archive_fragments.mdArchive tier
deeparchive_people.mdCold storage — searched via /recall only
deeparchive_loops.mdCold storage
deeparchive_reflections.mdCold storage
deeparchive_fragments.mdCold storage
File format

Each file is plain UTF-8 text. Records are separated by ## Heading lines. Everything between two headings is one record. There is no required internal structure — Claude reads free-form prose just as well as bullet points.

## Jane Smith
Works at Acme Corp, product manager. Met at the 2024 conference.
Loves hiking. Has a dog named Biscuit.
– Memory: important

## Bob Jones
Old college friend. Lives in Portland now.
Hasn't been in touch since 2022.
Seeding memory from a zip file

You can pre-populate your memory by importing a plain-text zip. Create one in any zip tool — no special software needed.

1 Create one or more .md files using the format above. You only need to include the files you want to import — the rest are left untouched.
2 Zip them up. Files must be at the root of the zip (not inside a folder), and named exactly: people.md, loops.md, etc.
3 In the app, type /import and select your zip file. You'll see a summary of what's in the zip and what will be skipped, then confirm with "overwrite".
Partial imports are safe. If your zip only contains people.md, only that file is overwritten. All other files stay as they are.

Backups & Portability

WhosWhoZoo has two export formats. They serve different purposes and have different portability characteristics.

Encrypted backup — /export → .whoszoo

Produces a single encrypted binary file. All 12 memory files are bundled together, compressed, and encrypted with AES-GCM using a password you choose. The encryption uses PBKDF2-SHA256 with 600,000 iterations — strong enough to resist brute-force attacks if you use a decent password.

Asks for your passphrase before exporting, and records the export in /security. Note the two passwords do different jobs: the one you type in the export dialog encrypts the resulting file, and whoever runs the export chooses it — so it protects the backup afterwards but authorises nothing. Your passphrase is what gates the export itself.

Fully portable. A .whoszoo file is not tied to your Cloudflare account, your Worker URL, or your Access Key. It can be decrypted and imported on any WhosWhoZoo installation — just supply the password you used when you exported it. This is the right format for migration, long-term backups, and disaster recovery.

The file can only be opened by WhosWhoZoo's /import command — there is no third-party tool that understands the format. If you lose your backup password, the file cannot be recovered. Store the password somewhere safe.

Plain-text zip — /export-plain → .zip

Produces a standard zip containing your 12 .md files as plain text — readable in any text editor, importable with any zip tool. No password required to open.

Unencrypted. Anyone who gets this file can read everything in your memory. Use it for editing or seeding, not for long-term storage. Asks for your passphrase before exporting, and records the export in /security — so a complete copy of your memory can't be taken from an unattended, logged-in device without you finding out.

Also portable — a plain-text zip can be imported on any installation. Partial zips work: include only the files you want to overwrite and the rest are left untouched.

Moving to a new Cloudflare account
1 In the app, type /export. Choose a strong password and download the .whoszoo file. Store the password somewhere safe — it cannot be recovered if lost.
2 Run the setup wizard at whoszoo.app/setup on the new Cloudflare account. This creates a new Worker, a new KV namespace, and a new Access Key.
3 Open the app on the new installation, complete setup (set your passphrase), then type /import.
4 Select your .whoszoo file and enter the backup password. Your memory files are restored exactly as they were.
The .whoszoo file is decrypted entirely in your browser — your backup password never leaves your device and is never sent to the worker or Cloudflare.

Memory Lifecycle

Claude has a finite context window (~200K tokens). If active memory plus archive grows too large, chat requests fail. The three-tier system lets you keep every record forever while only loading what's currently relevant.

The three tiers
Active The 4 live files (people.md, reflections.md, fragments.md, loops.md). Always loaded into Claude's context. ~180K token combined cap with archive.
Archive The 4 archive_*.md files. Loaded only when the 📦 Archive toggle is ON. Older records that aren't current but might be relevant.
Cold storage The 4 deeparchive_*.md files. Never auto-loaded. Searchable via /recall. Unlimited size — records here never count against Claude's context window.
Move records down the ladder (active → archive → cold)
/archive [name] Manual move to archive
/archive-review AI surfaces candidates from active → archive
/deep [name] Manual move to cold storage
/deep-review AI surfaces candidates from archive → cold storage
Edit modal buttons Open any record with /edit [name] — tap → Archive or → Cold to move in one tap
Move records up the ladder (cold → archive → active)
/restore [name] Restore a record from archive or cold storage back to active — works from any tier
Inspect what's where
/browse [tier] [file] List all records in a file with token sizes. Examples: /browse people, /browse archive people, /browse cold fragments
/diagnostics Full memory state with per-tier breakdown, usage percentage, and track-aware suggestions when a threshold is crossed
/recall [name or topic] Search cold storage by heading. Bare /recall browses all cold records grouped by file.
Compact within a tier (alternative to moving)
/compact [name] Shrink a single verbose record in place — choose Normal / Medium / High level in the preview
/compact-review AI surfaces the most verbose records across active memory — tap Load on each to choose a level
Login-time teaching nudges

At every login WhosWhoZoo checks combined memory (active + archive) against the 180K token cap. If a threshold is crossed, a system message appears in chat:

70% First time: full intro explaining the three tiers and what to do next. Subsequent crossings: a one-line nudge with the relevant commands.
85% Stronger nudge. If archive is large, suggests cold storage commands alongside archive tools.
95% Urgent — turning Archive ON will push the total past Claude's context window and cause requests to fail.

The intro message only fires once per "growth cycle" — the flag resets if you drop below 50% (e.g. after a big archiving session), allowing re-introduction if memory grows again later.

/diagnostics also shows a 💡 Suggestions block with track-aware commands whenever a threshold is crossed.

When to do what
1 First few months: just type. Memory grows naturally. No action needed.
2 When 70% hits: start archiving. Run /archive-review or open a record with /edit and tap → Archive.
3 When 85%+ hits with a substantial archive: time for cold storage. Run /deep-review or tap → Cold in the edit modal.
4 Don't worry about losing records. /recall finds anything in cold storage. /restore brings it back in one command.
Context window overflow error. If combined memory exceeds the limit mid-session, the worker returns an actionable error message instead of a raw API failure — it tells you exactly which command to run to reduce size.

Memory Audit

The audit checks for integrity issues in your memory files — it does not nudge you on memory size (that's the Memory Lifecycle teaching ladder above).

What it checks
Broken metadata characters, malformed section headers, date inconsistencies, near-duplicates, and name typos. The first three are free (pure regex). Near-duplicates and name mismatches use Haiku.
Commands
/audit — free Quick scan over active and archived files.
/audit deep — Quick scan + Haiku-assisted deep scan (~3¢). You confirm the cost estimate before any API call is made.
/audit ignored — list dismissed findings; per-row Un-ignore + manual Prune ghosts button.
Findings are read-only
Every fix is manual via the existing Edit Record modal — the audit never writes to your memory. Each finding card has two actions: Open (jumps to the edit modal) and Ignore (suppresses that exact issue in future audits). Ignored findings persist in KV and auto-prune if the target record is deleted.

Troubleshooting

Claude isn't responding or returns an error
Your Anthropic API key may be invalid, exhausted, or not yet active. Go to Settings → API Keys → Anthropic and paste a fresh key. Check your credit balance at console.anthropic.com.
Claude returns "daily spend cap reached" (402 error)
Your daily Anthropic spend cap has been reached. Go to Settings → Daily spend cap and increase the limit or set it to Never. The cap resets at midnight UTC. OpenAI TTS and ElevenLabs voices are unaffected — only Claude API calls are capped.
Claude returns "cap check failed" (503 error)
The worker could not read the daily cap state from KV. This is a transient error — the cap check fails closed (blocks requests) to protect against runaway spending. Try again in a moment. If it persists, check your Cloudflare Workers status page.
Voices aren't working
Check which voice is selected (Marin/Onyx use OpenAI; Brittney/Callum use ElevenLabs). Go to Settings → API Keys and update the relevant key. If the key is fine, check your usage quota at the provider's dashboard.
I forgot my passphrase
On the login screen, tap Forgot passphrase? and enter your Access Key instead. This lets you set a new passphrase without losing your data.
The app shows the setup screen instead of login
This happens in a fresh browser or incognito window — the saved Worker URL isn't available. Enter your Worker URL (https://whoszoo-worker.<your-account>.workers.dev), your Access Key, and set a passphrase to connect.
I saved a bad API key and now things are broken
Go to Settings → API Keys. Find the affected key and tap Clear override (appears under keys you've saved in-app). This removes the bad value and reverts to the key set during setup.
The app auto-locked and I can't remember my timeout setting
Log back in with your passphrase, then go to Settings → Auto-lock to change the timeout. The default is 30 minutes of inactivity.
I want to move my data to a new Cloudflare account
See Backups & Portability → Moving to a new Cloudflare account above for step-by-step instructions. The short version: export with /export, run the setup wizard fresh on the new account at whoszoo.app/setup, then restore with /import using your backup password. Your .whoszoo file is not tied to your old account — it works on any installation.
